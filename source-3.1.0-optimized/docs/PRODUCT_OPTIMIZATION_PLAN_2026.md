## 一、计划摘要

∞未来 AI 已经具备无限画布、图片节点、视频节点、多 API、多 Key、生成队列、素材库、角色资产、漫剧生产流、字幕配音、成片时间线、3D 导演台、ComfyUI 接入和本地项目管理等能力。软件不再处于“缺少功能”阶段，而是进入“统一管理、降低学习成本、提高产出稳定性”阶段。

本计划不以继续堆积按钮和页面为目标，而是把现有能力收拢成一套非技术用户也能理解、复用、控制成本并稳定交付的 AI 创作生产系统。

### 核心升级方向

1. 用“模型能力中心”统一管理不同厂商和模型的差异。
2. 补齐视频首尾帧、多关键帧、编辑、延长和多类型参考能力。
3. 让每个参考素材都有明确用途，减少角色、风格、构图和场景互相污染。
4. 将多节点保存为可复用的组合工作流。
5. 建立分支生成、结果对比、人工通过和下游传递机制。
6. 将∞小子从问答助手升级为可提案、可预览、需确认才执行的画布助手。
7. 建立模型费用、生命周期、输出来源和商业交付档案。

## 二、产品定位

### 目标用户

- 不熟悉 API、模型参数和节点工作流的创作者。
- 需要制作 AI 漫剧、短剧、广告、分镜、角色设定和视频的个人或小团队。
- 希望使用自己的 API 和 Key，并保留本地项目控制权的用户。

### 产品主张

∞未来 AI 不应成为“把很多 AI 页面放在一个软件里”，而应成为：

> 一个能理解创作目标、组织角色与场景资产、调度多个 AI 模型、记录生成过程、控制费用风险，并把镜头完整交付出去的本地 AI 创作工作台。

## 三、升级原则

1. **先统一规则，再增加功能**：任何新模型、新节点或新页面都必须接入统一能力档案、错误处理和输出档案。
2. **普通中文优先**：用户看到的是“首帧”“尾帧”“角色参考”，不是接口字段和协议名。
3. **逐步展示复杂度**：默认界面只显示完成当前任务必需的选项，高级参数按需展开。
4. **不静默改变用户选择**：自动更换模型、尺寸、Key、参考图用途或计费路径前必须说明并确认。
5. **生成结果可追溯**：每个输出都必须知道由哪个模型、哪组参考、哪份提示词和哪次操作生成。
6. **失败时保留有用成果**：任何重试、转换、尺寸校验和扩图失败都不得清除上一份成功结果。
7. **本地优先、外部操作可控**：项目、Key、素材和产出默认本地保存，上传、分享和云同步必须明确由用户触发。

## 四、当前基础与差距

| 领域 | 当前基础 | 主要差距 | 决策 |
| --- | --- | --- | --- |

| 图片生成 | 比例、清晰度、自定义尺寸、精准输出校验 | 缺少统一的分支对比和选片流程 | 增加变体对比台 |

## 五、优先级路线

## P0：必须先完成

### P0-1 模型能力中心与生命周期管理

#### 用户问题

当前不同图片和视频模型支持的参考数量、比例、尺寸、时长、首尾帧、编辑和计费方式不同，但节点界面仍然会显示较多通用选项。用户只能试错，失败后才知道某个模型不支持当前参数。

#### 升级内容

- 建立统一 `ModelCapabilityProfile`。
- 记录文本、图片、视频、音频和多模态能力。
- 记录可用操作：生成、编辑、扩图、放大、首尾帧、多关键帧、延长、循环、音频和口型。
- 记录支持的尺寸、比例、分辨率、时长、文件类型、参考数量和大小限制。
- 记录计费单位、参考价格、开始日期、停用日期和替代模型。
- 选择模型后动态生成表单，只显示当前模型支持的控件。
- 导入未知模型时使用安全默认档案，不猜测高风险能力。
- 建立模型停用预警、替代建议和项目批量迁移工具。

#### 验收标准

- 至少覆盖当前内置和用户已配置的图片、视频、聊天和 TTS 模型。
- 节点不得展示已确定不支持的参数。
- 运行前能一次列出全部能力不匹配问题。
- 模型停用不得导致旧项目无提示失败。
- 能力档案必须可版本化，本地自定义档案不被更新覆盖。

### P0-2 视频导演型节点

#### 升级内容

- 文生视频。
- 单张图生视频。
- 首帧 + 尾帧。
- 多关键帧和关键帧时间位置。
- 视频编辑、视频风格化和局部修改。
- 向后延长和向前延长。
- 循环视频。
- 调整时长、速度和画面比例。
- 图片、视频和音频混合参考。

#### 交互要求

- 用户先选择“我想做什么”，再根据模型能力显示可用选项。
- 首帧、尾帧、关键帧和参考视频使用不同图标和标题，不只依赖连线顺序。
- 提交前显示最终的尺寸、时长、参考数量、预计费用和不支持项。
- 生成后记录请求尺寸、实际尺寸、实际时长、编码和音轨状态。

#### 验收标准

- 不支持首尾帧的模型不得显示对应入口。
- 多关键帧的时间顺序必须可视化并能调整。
- 延长和编辑必须保留原视频，以新版本存储。
- 返回可用视频但尺寸或时长不匹配时，保留结果并显示明确差异。
- 真实 API 验收至少覆盖一个文生视频、一个首尾帧和一个视频延长模型。

### P0-3 参考素材用途与约束

#### 升级内容

每个参考素材增加 `referenceRole`：

- `character`：角色身份与面部。
- `costume`：服装结构和材质。
- `scene`：场景与空间关系。
- `object`：道具和物体外观。
- `style`：画风、光影、色彩和质感。
- `composition`：构图和镜头位置。
- `source`：需要编辑的原图或原视频。
- `first-frame`：视频首帧。
- `last-frame`：视频尾帧。
- `keyframe`：中间关键帧。
- `motion`：动作和镜头运动参考。
- `audio`：音频、节奏或口型参考。

#### 验收标准

- 参考用途可在节点缩略图上直接查看和修改。
- 同一节点出现两个首帧、两个尾帧或缺少必需原素材时立即报错。
- 提交给不同模型时，适配器必须将用途转换为正确的接口字段和提示词说明。
- 修改用途后必须使项目成为新的可撤销版本。

### P0-4 费用中心与预算保护

#### 升级内容

- 按模型记录图片张数、视频秒数、输入素材、分辨率、音频时长和 token 的计费方式。
- 支持用户手动维护中转站或企业账号的实际价格。
- 提交前显示预计费用区间，不能精确计算时明确标注。
- 增加项目预算、每日预算和单次任务预算。
- 显示自动重试、扩图、候选分支和备用模型可能带来的额外费用。
- “价格优先、速度优先、质量优先”只作为可预览的路由建议，不擅自替换模型。

#### 验收标准

- 批量任务提交前必须显示预计请求数、视频总秒数和费用区间。
- 超过预算时默认阻止，需用户明确确认后才能继续。
- 价格数据必须显示来源时间和是否为用户自定义。
- 任务结束后记录估算值、实际请求和差异原因。

## P1：核心产品能力

### P1-1 组合节点与可复用工作流

#### 升级内容

- 框选多个节点后保存为组合节点。
- 选择对外暴露的输入、输出和参数。
- 组合节点支持展开编辑、折叠使用和单步运行。
- 建立工作流版本号、修改说明和兼容性检查。
- 支持导出、导入和本地模板库。
- 第一批内置组合：角色定妆、三镜头分镜、图片转视频、首尾帧视频、广告变体和漫剧单镜头。

#### 验收标准

- 组合节点不能丢失内部连线、节点位置、模型绑定和参考用途。
- 旧版本项目即使缺少新组合定义，也能展开原始节点继续使用。
- 导入工作流时不得导入 Key、真实本地路径和用户隐私数据。

### P1-2 生成分支、变体对比与选片

#### 升级内容

- 一次创建多个模型、提示词、种子、比例、时长或参考组合的候选分支。
- 为图片提供宫格、并排和放大同步查看。
- 为视频提供同步播放、同一时间点对比和逐帧定位。
- 状态统一为：未查看、候选、通过、淘汰、返工。
- 选中的胜出版本可替换当前节点输出或作为新版本传给下游。
- 对比界面显示模型、参数、耗时、估算费用、实际尺寸和失败信息。

#### 验收标准

- 未通过的候选版本不能被批量交付。
- 替换胜出版本必须可撤销。
- 下游已生成输出时，更换上游版本必须提示影响范围，不自动删除旧输出。

### P1-3 媒体处理工具节点

#### 第一批节点

- 提取首帧、尾帧和指定时间帧。
- 图片缩放、转换格式、改变画布比例和本地背景延展。
- 视频裁剪、拼接、调速、循环和音轨分离。
- 音频音量、混音、静音和时长对齐。
- 字幕烧录、字幕格式转换和字幕时间校正。

#### 原则

- 本地可完成的操作默认不调用 AI API。
- 真实裁剪、延展、改速和转码必须在节点上显示状态，不与预览的 `contain` 显示混淆。
- 工具输出必须作为新媒体版本，不覆盖源文件。

### P1-4 画布执行助手

#### 目标交互

用户输入“用当前角色做一个三镜头的 16:9 短片”后，∞小子应：

1. 读取当前项目的角色、场景、可用模型、Key 状态和预算。
2. 生成将要新增、修改、连接和运行的操作清单。
3. 在画布上显示半透明预览，不立即修改真实项目。
4. 显示预计请求数、费用、耗时和模型限制。
5. 用户确认后作为一次可撤销事务执行。
6. 运行失败时只修复必要节点，不擅自重建全部画布。

#### 安全边界

- 未确认前不调用付费 API。
- 不更改 Key、存储目录、许可证和更新配置。
- 不删除项目、节点、素材和已生成版本。
- 必须将自动操作写入操作记录。

#### 验收标准

- 至少支持创建节点、连线、修改提示词、配置模型、建立组和准备队列。
- 执行前后项目差异可查看、可撤销、可重做。
- 对含付费请求的方案必须单独确认。

## P2：交付、检索与审片

### P2-1 产出来源与商业交付档案

每个图片、视频和音频输出记录：

- 供应商、模型、能力档案版本和请求协议。
- 提示词、参数、参考素材及用途。
- 请求尺寸、实际尺寸、请求时长和实际时长。
- 生成、扩图、放大、转码和人工编辑历史。
- 生成时间、文件哈希、本地相对路径和授权备注。
- 审批状态和交付批次。

导出生产包时生成人类可读的交付清单和机器可读的 `provenance.json`。

### P2-2 智能素材检索与资产集合

- 在现有文字搜索、标签和重复检测基础上增加本地视觉特征。
- 支持“找这个角色”“找相似构图”“找同一场景”“找没有使用的素材”。
- 建立角色、场景、道具、画风和镜头智能集合。
- 角色资产更换时显示影响的分镜和输出。
- 索引必须可重建，索引损坏不得影响原始素材。

### P2-3 审片包、评论和客户确认

- 先实现本地可导出的只读审片包，不先建设实时云协作。
- 审片包支持图片放大、视频播放、指定时间点评论、通过、返工和总结。
- 评论导入软件后绑定到对应输出版本和时间点。
- 已通过的版本被修改后自动失效，需要重新确认。
- 云端分享、实时多人和账号体系作为独立的后续决策，不纳入当前周期。

## 八、验收与质量门槛

### 通用验收

- 任何可付费操作在重复点击、页面重绘和网络重试下不得重复计费。
- 所有网络、媒体和错误日志必须脱敏。

- 预览继续使用 `contain`，真实裁剪、扩图和转码必须显示为独立操作。

1. 语法和脚本解析。
2. 单元测试和操作契约测试。
3. 画布、队列、设置、资产库和媒体预览冒烟测试。
4. URL DOM 安全、密钥脱敏和发布目录白名单。

## 九、成功指标

### 可用性

- 新用户从新建项目到第一次成功生成的中位时间低于 10 分钟。
- 因选择不支持参数造成的请求失败降低 80% 以上。
- 可恢复异步视频任务的恢复成功率达到 95% 以上。
- 尺寸、时长和参考用途不匹配必须 100% 显示，不允许静默修改。

### 生产效率

- 内置组合工作流可将常见任务的手动节点搭建步骤减少 50% 以上。
- 批量候选生成后，用户可在一个界面完成对比、通过和下游传递。
- 从剧本通过到导出审片包不需要离开软件使用外部文件拼接工具。

### 成本和可靠性

- 有价格档案的模型，任务前费用估算覆盖率达到 90% 以上。
- 不存在由界面重复点击和普通网络错误自动换 Key 导致的重复计费。
- 项目保存、升级、回滚和素材迁移不丢失用户内容。
- 正式交付的每个输出都能找到来源档案。

## 十、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 各 API 参数快速变化 | 能力档案过期、请求失败 | 档案版本化，允许用户修改，失败后记录经过确认的能力修正 |
| 功能增加使节点过于复杂 | 新用户不会使用 | 先选任务模式，再动态显示必需选项，高级参数折叠 |
| 组合节点引入嵌套状态 | 保存、撤销和连线变复杂 | 先实现单层组合，验证后再允许嵌套 |
| AI 助手自动操作错误 | 破坏画布或产生费用 | 使用差异预览、用户确认、事务撤销和付费二次确认 |
| 价格信息不准确 | 费用误判 | 显示估算区间、数据时间和用户自定义标记，不伪装成精确账单 |
| 本地视觉索引占用空间 | 大项目索引较慢 | 可选开启、后台分批、可清理重建，不影响原始素材 |
| 实时云协作范围过大 | 账号、服务器、同步冲突和成本急剧上升 | 当前周期只做本地审片包，云协作单独立项 |

## 十一、本周期不优先的事项

- 不为了“看起来功能多”增加重复入口。
- 不建立新的大型云端账号和实时协作系统。
- 不自动发布或上传用户产出。
- 不以支持模型数量作为唯一竞争指标。
- 不让每个模型的所有原始参数直接堆在节点上。
- 不允许助手在无确认时执行付费请求或破坏性操作。
- 不因升级数据结构而破坏现有项目、历史记录和素材引用。

## 十二、立项结论

本计划建议正式立项，并按以下顺序实施：

1. 模型能力中心和生命周期管理。
2. 视频导演型节点和参考用途。
3. 费用中心和预算保护。
4. 组合节点、分支生成和结果对比。
5. 媒体工具节点和画布执行助手。
6. 产出来源、智能素材和本地审片包。

执行过程中，任何新功能都必须回答四个问题：

1. 普通用户能否知道该在什么时候使用它？
2. 软件能否在提交前判断当前模型是否支持？
3. 失败、重启或升级后能否保留已有成果？
4. 用户能否看到成本、影响范围和下一步？

只有四个问题都有明确答案时，该功能才算完成。
