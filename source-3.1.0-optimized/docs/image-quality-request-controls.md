# 图片生成请求与画质排查

## 本次范围

无限画布图片节点新增原文直通、请求预览、最近提交记录。新节点默认原文直通和 high 质量；旧节点已有 quality 值不自动升级，避免增加既有任务费用。AI 漫剧工作台的 Skill 编译流程保持不变。图片供应商层在指定模型时默认锁定该模型，未授权不再换成其他模型。

## 使用

1. 图片节点质量选择“高质量”，提示词选择“原文直通”。
2. 点击“请求预览”，核对供应商、协议、模型、尺寸字段、质量、参考图数量和完整文本。预览不调用接口。
3. 原文直通保留前后空白及换行，不添加机位、风格标签、通用规则、画布上下文或参考角色说明。需要这些附加内容时手动切换“增强上下文”。手动点击优化提示词仍会更改编辑框内容。
4. 点击生成后，可从“上次请求”查看提交时快照。参考图由连线决定；上游素材若尚未生成，预览后需要重新核对。
5. 质量参数与像素尺寸互相独立。high 需供应商支持，可能更慢、更贵；并非所有接口、账号或中转路由支持，不保证画质提升。
6. 原图尺寸不匹配时保留成果并提示未达标；不扩图、不插值放大、不静默降低尺寸重试。

## 模型与失败

- 锁定节点所选模型，不因模型不可用而改用其他模型。别名仅按既有供应商映射解析。
- 画布生成禁用参考板合成、参考图描述再生成等隐式回退。
- 404 中含模型、账号组、权限或额度错误时，不再尝试另一条 /v1 地址。明确路径不存在的兼容处理仍保留。
- 上述措施不控制供应商内部采样、放大或模型转发，因此文件宽高匹配不能证明原生细节。

首次测试未完整复用正式密钥池流程：直接读取第一把 Key，auto 组因模型错误未出图，未进入 high 组。这不能证明整个供应商或模型不可用。

第二轮已复用正式 providerApiKey → runImageNow → imageGenerateRequest 调用链，使用不写入用户配置的独立副本。共发出两次生成请求，依次选择“通用 Key 2”和“通用 Key”；均以 gpt-image-2-adobe、2304x4096、auto 提交 4715 字符原文。两次均返回 HTTP 404：当前账号组没有支持该模型的配置。没有重试其他模型，没有出图，没有执行 high 组。此后停止付费测试。

两把 Key 的只读 /models 与 /v1/models 查询均成功，当前公布的图片模型为 gpt-image-2，没有 gpt-image-2-adobe。缓存列表仍有 adobe 名称。供应商目录不等同于所有内部路由能力，不能据此否定过去成功。

2026-09-05 23:12:48 的历史记录确实标有 gpt-image-2-adobe，结果为 2304x4096。但旧队列将最初选择的模型写入历史，忽略适配器返回的 result.model；旧供应商层又允许模型回退。因此这条旧记录不足以证明实际请求模型，也不足以证明当时一定发生过回退。当前证据无法区分供应商路由变化与旧记录归属问题。

新版历史、变体和溯源采用适配器返回的模型标识，同时保留 requestedModel、逐次请求快照和逐图模型；上次请求显示安全 Key 标识、状态及返回像素。该标识只是适配器实际请求模型，不是供应商内部模型证明；不回写旧历史，不保存密钥内容。重新生成节点清除旧请求和输出模型。

证据：image-quality-normal-chain-report.json（本线程可视化输出目录）。当前仍无同模型成功对照图，不能宣称画质已经提升。

未修改用户的密钥、供应商选择、源提示词、图片或项目。失败请求是否收费需以供应商账单为准。
